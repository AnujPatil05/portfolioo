The premise was simple: most developers write inconsistent commit messages. Most release note generators either require rigid formats (Conventional Commits) or produce vague summaries. I wanted to see if an LLM could bridge that gap — inferring structure from unstructured input.

The experiment confirmed that the approach works, with caveats. The interesting finding was about **context window management**: giving the model 5–10 surrounding commits as context dramatically improved its ability to group related changes, even when individual messages were cryptic. Single-commit summaries were often too literal; grouped summaries were genuinely useful.

The unsolved problem — scope mixing when commits touch unrelated areas — is a data preprocessing problem, not an LLM problem. The model is trying to be helpful by connecting related changes. But when "related" means "happened on the same day", that's not a useful grouping criterion.
