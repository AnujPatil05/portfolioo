The most technically interesting part of this project wasn't the voice synthesis — it was the tension between **specialisation** and **generalisation** in the fine-tuned model.

When we fine-tuned on instructor course material, the model got better at course-specific questions. But it also got worse at adjacent questions that required general knowledge. The fine-tuning was pulling the model toward the training distribution at the cost of breadth.

We partially addressed this with the RAG layer — letting the retrieval system handle course-specific facts while the base model handled reasoning. But the boundary between "course knowledge" and "general reasoning" is fuzzy, and we never found a clean separation.

The voice cloning component worked, but it introduced a latency problem we underestimated. A 4-second wait is acceptable for a document query. It's not acceptable in a conversation. The lesson: **latency requirements are different for conversational interfaces than for query interfaces**. We designed the architecture as if it were a query system. It was actually a conversation system.
